# MY LIFE — 수익화 설계와 실행 계획

Status: `PROPOSAL — NOT IMPLEMENTED`

작성/공식 정책 확인: 2026-10-05. 가격·상품·출시 일정은 가설이며 사용자 승인 전 확정하지 않습니다. V1 앱에 결제, 광고 SDK, 회원/서버 또는 paywall을 추가하지 않습니다.

## 1. 제품 방향

MY LIFE의 가치는 빠른 개인 기록과 안심하고 다시 볼 수 있는 기록 보존입니다. 기록 내용·사진·결제 원문 판매나 타깃 광고를 기본 수익원으로 삼지 않는 방향을 권장합니다. 현재 기록의 조회/삭제를 결제 뒤로 잠그지 않습니다.

권장 순서: 무료 로컬 V1 → 사용성/재사용 검증 → 선택적 고급 기능 → 운영 가능한 Cloud 구독. 수익은 보장되지 않으며 유지율·지불 의사·원가를 먼저 검증합니다.

## 2. 상품 후보와 대안

| 후보 | 제안 내용 | 가격 실험 가설 | 선행 조건 |
| --- | --- | --- | --- |
| Free | 현재 Memo/Expense/Photo/Timeline/Home/기본 Finance | 무료 유지 | V1 안정화 |
| Local Pro | 향후 고급 회고/분석·개인화 등 지속 서버 비용 없는 기능 | 일회성 ₩19,900 후보 | 구체 기능·지불 의사·스토어 구매/복원 검증 |
| Cloud Plus | 향후 기기 간 동기화, 관리형 보관 서비스 | 월 ₩3,900 / 연 ₩39,000 후보 | 회원/삭제, Cloud 안정성·용량 한도·원가·복구 운영 |

이는 기능 제공 약속이 아닙니다. 아직 없는 기능을 상품처럼 노출하지 않습니다. 데이터 이동을 위한 기본 수동 내보내기/Backup는 안전성 기능으로 별도 설계하고, 사용자가 자신의 기존 데이터를 가져가는 권리를 유료로 막지 않는 방향을 제안합니다.

일회성 구매는 반복 원가가 없는 기능에 적합합니다. Cloud/AI를 무제한 평생 상품에 포함하지 않습니다. 두 유료 상품을 동시에 시작하지 않고 지불 의사 검증 결과에 따라 하나부터 진행합니다.

## 3. 결제와 권한 경계

- 앱 내 디지털 기능 판매는 Apple IAP/Google Play Billing을 기본 경로로 설계합니다. 국가별 예외/대체 결제 제도는 실제 출시 시 검토하고 지금 우회 링크를 만들지 않습니다. [Apple 결제·구독 정책](https://developer.apple.com/app-store/review/guidelines/), [Google Payments 정책](https://support.google.com/googleplay/android-developer/answer/9858738?hl=en)
- 반복 구독은 계속 제공되는 가치가 있어야 합니다. 단순히 기존 로컬 기록 사용을 위해 구독을 강제하지 않습니다. [Apple 구독 기준 3.1.2](https://developer.apple.com/app-store/review/guidelines/#subscriptions)
- 일반 지출 Record는 사용자의 가계 기록입니다. MY LIFE 유료 상품 거래/구독 DB와 섞지 않습니다.
- 향후 purchase adapter → 서버 검증 → entitlement → UI 권한 흐름을 설계합니다. Flutter/로컬 boolean만으로 유료 권한을 확정하지 않습니다.
- 결제 pending/실패/중복/취소/환불/갱신 실패/만료/구매 복원을 처리하고 store transaction ID로 멱등성을 보장합니다.
- 스토어 내 구매 복원은 MY LIFE 로그인과 별개로 검토합니다. 계정은 선택적 cross-platform Cloud 권한 연결을 담당합니다.
- 만료/환불 시 기존 기록을 삭제하거나 조회를 차단하지 않습니다. Cloud 쓰기/새 업로드는 제한할 수 있으나 유예·내려받기·보존/삭제 기간을 사전에 안내해야 합니다.
- 가입·구독·Cloud 동의는 분리하고 가격/주기/자동 갱신/취소 경로를 구매 전에 표시합니다.

## 4. 원가와 손익 — 예측이 아닌 검증용 계산

```text
월 기여이익 = 유료 사용자 수 × (사용자당 매출 × (1 - 수수료율) - 사용자당 변동 원가)
손익분기 유료 사용자 수 = 월 고정비 ÷ 사용자당 기여이익 (양수인 경우)
```

사진 저장 용량·다운로드 전송량·인증/DB·백업/복구·지원 비용을 모두 측정합니다. 세금/환불/개발자 인건비와 연간 결제의 매출 인식은 별도이며 아래 계산에 포함되지 않습니다.

예시 가정: 월 가격 ₩3,900, 수수료 30%, 변동비 ₩500/유료 사용자, 고정비 ₩100,000/월.

- 사용자당 기여이익: ₩3,900 × 0.70 - ₩500 = ₩2,230.
- 손익분기: 약 45명의 유료 사용자 (₩100,000 ÷ ₩2,230, 올림).
- 월 활성 사용자 1,000명·전환율 2% 가정이면 유료 20명, 기여이익 ₩44,600, 고정비 차감 후 -₩55,400. 인건비까지 고려하면 더 낮습니다.

30%는 보수적인 계산 가정이지 모든 거래의 실제 수수료가 아닙니다. 적용 국가·상품·가입 프로그램별 실제 수수료를 출시 시 확인합니다. [Google 수수료 안내](https://support.google.com/googleplay/android-developer/answer/112622?hl=en), [Apple Small Business 프로그램](https://developer.apple.com/app-store/small-business-program/)

Cloud 용량 한도, 파일 크기/월 전송량 한도, 비용 알림과 신규 가입 일시 중지 기준을 결정하기 전 가격을 확정하지 않습니다. 무료 사용자 비용도 고정비/별도 원가에 포함해야 합니다.
